# Форматы данных

Единый справочник форматов. Все системы используют эти правила; изменение формата делается только вместе с обновлением этого документа, тестов и (для сохранений) миграции.

## 1. Координаты

| Понятие                   | Единица                         | Примечание                                             |
| ------------------------- | ------------------------------- | ------------------------------------------------------ |
| Позиция сущности (`Vec2`) | пиксели мира, дробные допустимы | `x` вправо, `y` вниз, начало в левом верхнем углу мира |
| Тайл                      | целые `(tx, ty)`                | тайл покрывает пиксели `[tx*32, (tx+1)*32)`            |
| Чанк                      | целые `(cx, cy)`                | содержит тайлы `[cx*32, (cx+1)*32)`                    |
| Индекс тайла в чанке      | `ly * 32 + lx`                  | `localTileIndex(lx, ly)`                               |

Помощники для чанков и мира (M1.1, `src/core/coords.ts`): `worldTileIndex(tx, ty)` — индекс клетки в плоском массиве всего мира (по строкам; вне мира — `RangeError`), `isChunkInWorld`, `chunkOriginTile`, `chunkRectWorld`, `chunkCenterWorld`, `chunksInRadius(cx, cy, radius)` — только чанки внутри мира, порядок: по квадрату расстояния, затем `cx`, затем `cy`.

Размеры: тайл 32 px, чанк 32×32 тайла, мир 8×8 чанков = 256×256 тайлов = 8192×8192 px. Все преобразования только через `src/core/coords.ts`. Деление «вниз» (`Math.floor`), в том числе для отрицательных значений.

## 2. Идентификаторы

| Тип             | Формат                             | Пример                            |
| --------------- | ---------------------------------- | --------------------------------- |
| `PlayerId`      | строка                             | `p1` (единственный игрок в v1)    |
| `WorldObjectId` | `` `${cx}:${cy}:${index}` ``       | `4:3:17`, стабилен при одном seed |
| `ItemId`        | строка из `data/items.json` (M3)   | `scrap_metal`                     |
| Тип команды     | `ВЕРХНИЙ_РЕГИСТР_С_ПОДЧЁРКИВАНИЕМ` | `SET_PLAYER_POSITION`             |
| Событие         | `область:действие`                 | `player:moved`                    |

## 3. Seed

- Пользовательский текст проходит `sanitizeSeedText`: Unicode NFC, управляющие символы заменяются пробелом, пробелы сжимаются, обрезка до 64 символов (по кодовым точкам). Пустой seed недопустим.
- Число для генератора: `hashString(очищенный текст)` (FNV-1a, 32 бита).
- Seed чанка: `hashInts(worldSeed, cx, cy)`.
- Случайный текст для кнопки «случайный мир»: `generateSeedText()`, 8 символов из `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`.

## 4. GameState (версия формата 1)

```ts
interface GameState {
  version: number; // SAVE_FORMAT_VERSION
  worldSeed: string; // очищенный текст seed
  tick: number; // такт симуляции
  worldGenVersion: number; // WORLD_GEN_VERSION: версия алгоритма генерации мира (решение D3)
  players: Record<PlayerId, PlayerState>;
}
interface PlayerState {
  id: PlayerId;
  position: Vec2; // пиксели мира
}
```

`worldGenVersion` хранится рядом с `worldSeed`: мир однозначно определяется парой (seed, версия генератора). Поле добавлено в формат версии 1 на месте, без миграции (сохранений ещё нет). Любое изменение алгоритма или salt после первого использования требует нового `WORLD_GEN_VERSION`.

Правила: только простые сериализуемые данные (без классов, функций, `Map`/`Set`, ссылок на Phaser). Изменяется только обработчиками команд.

Новые поля (инвентарь, постройки, квест, сигнал) добавляются на своих этапах. Каждое такое изменение: повысить `SAVE_FORMAT_VERSION`, добавить миграцию (M6), обновить этот раздел.

## 5. Команда

```ts
{ type: 'SET_PLAYER_POSITION', playerId: 'p1', tick: 0, position: { x, y } }
```

Результат: `{ ok: true }` или `{ ok: false, reason }`. Коды причин: `unknown_command`, `unknown_player`, `handler_error`, `invalid_position`, `out_of_bounds`. Новые коды добавляются здесь.

## 6а. Коды тайлов и биомов (M1, `src/systems/world/types.ts`)

Значения хранятся в `Uint8Array` чанка и входят в хеш мира, поэтому не меняются.

| Тайл (`Tile`) | Код | Биом (`Biome`) | Код |
| ------------- | --- | -------------- | --- |
| Water         | 0   | Water          | 0   |
| Sand          | 1   | Coast          | 1   |
| Grass         | 2   | Plains         | 2   |
| Forest        | 3   | Forest         | 3   |
| Stone         | 4   | Rocks          | 4   |
| Mud           | 5   | Swamp          | 5   |
| Concrete      | 6   |                |     |
| Path          | 7   |                |     |

### Параметры рельефа (M1.2, `src/data/worldgen.json`)

Проверяются при загрузке (`src/systems/world/worldData.ts`), ошибка называет путь к полю. Поля: `elevation` и `moisture` (`scale` в тайлах, `octaves` 1…8), `contrast`, `edge` (`strength`, `from`, `to`), `thresholds` (`water` < `sand` < `rock`, `swamp.moisture`, `swamp.maxElevation`, `forestMoisture`), `start` (`safeRadius` < `blendRadius`, `elevation`, `moisture`). Любое изменение значений после релиза требует нового `WORLD_GEN_VERSION`.

Рельеф клетки — чистая функция `(worldSeed, tx, ty)` (`createTerrainSampler`), поэтому на границах чанков швов нет. Классификация: вода → побережье → скалы → болото → лес → равнина (первое совпадение).

### Чанки и хеш мира (M1.3, `src/systems/world`)

- `generateChunk(plan, cx, cy)` — чистая функция: чанк зависит только от плана (то есть seed) и координат; массивы чанка — копии, не ссылки на план. Каждая клетка мира принадлежит ровно одному чанку.
- `ChunkManager`: радиус загрузки и выгрузки (выгрузки строго больше — гистерезис), очередь «ближе к центру, затем `(cx, cy)`», `step(budget)` грузит не больше `budget` чанков, выгруженные чанки хранятся в LRU-кэше (`maxCached`). События `chunk:loaded` и `chunk:unloaded` выпускаются один раз на смену состояния и только после согласования состояния. Порядок `loaded()` — `(cy, cx)`.
- Хеш мира и хеш чанка — 64 бита, 16 шестнадцатеричных знаков (`checksum.ts`). В хеш входят версия генератора, seed, и для каждого чанка в порядке `(cy, cx)`: координаты, тайлы, биомы, объекты (id, тип, x, y, принадлежность точке интереса); перед каждым разделом метка и число элементов. Разделы точек интереса и троп добавятся в M1.6 и M1.7, золотые значения в тестах тогда записываются заново (окончательные — в M1.8).

Реестр salt для производных seed — `src/systems/world/salts.ts` (значения заморожены тестом). Правила детерминизма логики (запрет неточных функций `Math`, `**`, обхода `for…in`/`Object.keys` в systems) — в `eslint.config.js` и `tests/architecture.test.ts`.

## 7. Формат сохранения (проект, реализация в M6)

```ts
interface SaveFile {
  version: number; // формат сохранения
  savedAt: string; // ISO-время записи
  playTimeMs: number;
  state: GameState; // см. выше
  deltas: unknown; // изменения мира: собранные объекты, постройки (уточняется в M3–M4)
}
```

Хранилище (idb-keyval): `ls:meta`, `ls:slot:1..3`, `ls:slot:N:prev`. Подробнее в `docs/ARCHITECTURE.md`, раздел 7.
