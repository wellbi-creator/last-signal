# Тестирование

## Как запускать автотесты

```bash
npm test            # один прогон
npm run test:watch  # в режиме наблюдения
```

## Этап M0

### Автоматические проверки (выполнены в среде разработки)

Тесты запущены **не через Vitest** (в среде разработки не было доступа к npm), а через встроенный тест-раннер Node с подменой `vitest` тонкой прослойкой. Файлы тестов те же, что запустит `npm test`. Перед сдачей этапа подтвердите прогон на своём компьютере (кейс M0-01).

| Набор                           | Файл                           | Проверок              |
| ------------------------------- | ------------------------------ | --------------------- |
| Генератор случайных чисел, хеши | `tests/core/rng.test.ts`       | 20                    |
| Очистка и генерация seed        | `tests/core/seed.test.ts`      | 12                    |
| Координаты, константы мира      | `tests/core/coords.test.ts`    | 8                     |
| Шина событий                    | `tests/core/eventbus.test.ts`  | 10                    |
| Состояние игры, создание ядра   | `tests/core/gamestate.test.ts` | 8                     |
| Команды                         | `tests/core/commands.test.ts`  | 9                     |
| Архитектурные правила           | `tests/architecture.test.ts`   | 6                     |
| **Итого**                       |                                | **73 из 73 пройдено** |

Дополнительно: проверка типов `tsc` в строгом режиме для `src/core`, `src/config.ts`, `src/platform.ts` и всех тестов, форматирование `prettier --check`.

Проверка того, что тесты умеют падать (мутации на копии проекта): `Math.random` в ядре, импорт Phaser в логике, изменённая константа Rng, удалённая проверка границ мира. Во всех четырёх случаях нужные тесты упали.
