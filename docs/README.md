# Последний сигнал

Браузерная 2D-игра о выживании, исследовании и строительстве. Вид сверху, пиксель-арт, постапокалипсис. Работает на компьютерах и телефонах.

**Стек:** Phaser 3 · TypeScript · Vite · Vitest · GitHub Pages.
**Статус:** этап **M0 (каркас)**. Игрового процесса пока нет; экран показывает, что каркас работает. План: `docs/ROADMAP.md`.

---

## 1. Что понадобится

- **Node.js 22 LTS** (подойдёт 20.19 и новее). Скачать: https://nodejs.org
- **Git**: https://git-scm.com
- Аккаунт на https://github.com (бесплатно)

Нет возможности установить Node.js? Откройте репозиторий в **GitHub Codespaces** (кнопка Code → Codespaces → Create): там Node.js уже есть, а бесплатного лимита хватает для разработки. Дальше выполняйте те же команды в терминале Codespaces.

## 2. Запуск на своём компьютере

Откройте терминал в папке проекта и выполните:

```bash
npm install        # установка зависимостей (один раз)
npm run dev        # запуск; адрес появится в терминале, обычно http://localhost:5173
```

Откройте адрес в браузере. Должен появиться тёмный экран с надписью «ПОСЛЕДНИЙ СИГНАЛ · Каркас M0».

### Команды

| Команда             | Что делает                                       |
| ------------------- | ------------------------------------------------ |
| `npm run dev`       | Запуск для разработки с автоперезагрузкой        |
| `npm run dev:lan`   | То же, но доступно с телефона в вашей Wi-Fi сети |
| `npm run build`     | Проверка типов и сборка в папку `dist/`          |
| `npm run preview`   | Запуск собранной версии для проверки             |
| `npm test`          | Автотесты                                        |
| `npm run typecheck` | Проверка типов TypeScript                        |
| `npm run lint`      | Проверка кода ESLint                             |
| `npm run format`    | Автоформатирование Prettier                      |

Перед первой отправкой на GitHub выполните по очереди `npm test`, `npm run lint`, `npm run typecheck`, `npm run build`. Всё должно проходить без ошибок. Если что-то не проходит, пришлите вывод терминала, я исправлю.

## 3. Проверка на iPhone

1. Компьютер и iPhone должны быть в одной Wi-Fi сети.
2. На компьютере: `npm run dev:lan`. В терминале появится адрес вида `http://192.168.x.x:5173`.
3. Откройте этот адрес в Safari на iPhone.
4. Пройдите кейсы **M0-06 … M0-11** из `docs/TESTING.md`. Главная проверка: строка `Rng(M0-DEMO): 21 44 61` должна совпасть на компьютере и телефоне.

Если страница не открывается, проверьте, что брандмауэр компьютера разрешает входящие подключения для Node.js. Для проверки без локальной сети можно сразу опубликовать игру на GitHub Pages (раздел 4) и открыть её по ссылке.

## 4. Публикация на GitHub Pages (бесплатно)

Один раз:

1. Создайте на GitHub пустой репозиторий (например, `last-signal`), без README и без `.gitignore`.
2. В папке проекта выполните (подставьте свой адрес репозитория):

   ```bash
   git init
   git add .
   git commit -m "M0: каркас проекта"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/last-signal.git
   git push -u origin main
   ```

3. В репозитории откройте **Settings → Pages**. В поле **Source** выберите **GitHub Actions**.
4. Откройте вкладку **Actions**: запустится workflow «CI и публикация на GitHub Pages». Дождитесь зелёной отметки.
5. Игра будет доступна по адресу `https://ВАШ_ЛОГИН.github.io/last-signal/`.

Дальше публикация происходит сама при каждой отправке в ветку `main` (`git push`). Если тесты, линтер, проверка типов или сборка не проходят, публикации не будет, а на вкладке Actions виден шаг с ошибкой.

**Файл `package-lock.json`.** Он появляется после первого `npm install`. Обязательно добавьте его в репозиторий (`git add package-lock.json`): он фиксирует версии пакетов, и сборка на GitHub будет совпадать с вашей.

## 5. Структура проекта

Подробно в `docs/ARCHITECTURE.md`. Кратко:

```
src/core/      логика без Phaser: состояние, команды, события, генератор случайных чисел
src/scenes/    сцены Phaser (на этапе M0: загрузка и экран-каркас)
src/main.ts    точка входа
tests/         автотесты
docs/          архитектура, форматы данных, тест-кейсы, дорожная карта, реестр графики
```

Главные правила: логика (`src/core`, будущая `src/systems`) не зависит от Phaser; изменять состояние игры можно только командами; в логике нет `Math.random` и `Date.now` (случайность только через `Rng`). Правила проверяются автоматически.
